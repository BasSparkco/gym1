## 2026-07-12 (Gym Demo)

Notes from the in-person demo:

1. `[x]` **Branch logos** — the gym has a logo, but in some cases each branch has its own logo. Add a setting (tenant settings / options) to choose: (a) one shared logo for all branches, or (b) per-branch logo. Need to design the upload flow for both cases (where in the UI to upload — tenant settings for the shared case, branch edit page for the per-branch case). Once uploaded, the logo should display in: the topbar (near the tenant/branch name), the branches list page, and the branch detail page.
   Fixed: `TenantSettings.logoMode` (`shared`/`perBranch`) + `logoUrl`, `Branch.logoUrl` (migration `20260712195120_add_branch_and_tenant_logos`); MinIO-backed upload/serve endpoints (`POST`/`DELETE /settings/logo`, `POST`/`DELETE /branches/:id/logo`, `GET /uploads/logos/:filename`, auth-gated); mode toggle + shared-logo upload on Settings → Options; per-branch upload on the branch edit page (shown only in per-branch mode); logo rendered in the sidebar/mobile topbar, branches list, and branch detail header. Full en/ar/he i18n. Verified end-to-end against dev Postgres/MinIO on disposable servers (API 3200 / web 3300): uploaded a branch logo and a tenant logo, confirmed auth-gated serving (200 authed / 401 unauthenticated), confirmed the branch edit page's upload section only appears in per-branch mode, then reverted all test data (deleted both test logos, reset `logoMode` to `shared`). `tsc --noEmit` and full production builds clean on both apps. Not yet deployed to production — pending review.

2. `[x]` **WhatsApp box ignores active language** — on the branch details page (e.g. `/app/branches/[branchId]` for "Platinum Fitness"), the WhatsApp card always renders in English even when Arabic or Hebrew is the active language. Should follow the same i18n as the rest of the page.
   Fixed: `WhatsAppCard.tsx` was fully hardcoded in English and never received `t`; it turned out `lib/i18n.ts` already had a complete unused `settings.whatsapp*` translation set (en/ar/he) sitting dormant. Wired the component up to consume `t` (passed down from the branch detail page) and added the 3 missing keys (`whatsappReconnecting`, `whatsappRefreshHint`, `whatsappGenericError`) in all three languages.

3. `[x]` **Employee name shown twice on user detail page** — at the top of an employee/user page we show employee name + username, then further down the page the employee name is displayed again. Remove the redundant second occurrence.
   Fixed: `/app/users/[userId]/page.tsx` had a redundant "Full Name" field in the Staff Details card duplicating the name already shown in the page header title. Removed the duplicate field.

4. `[x]` **Members list doesn't show profile pictures** — a member was added with a profile picture during testing, but the members list page still shows initials (first letters of the name) next to their name instead of the actual photo. Initials are fine as a fallback for members without a picture, but members who have one should show it in the list.
   Fixed: `/app/members/page.tsx` always rendered the initials avatar and never looked at `member.pictureUrl`. Now uses the existing `getMemberPhotoUrl` helper (same one already used on the member detail/edit pages) and shows the photo when present, falling back to initials otherwise. Verified end-to-end on disposable dev servers: uploaded a test photo for one member, confirmed only that member renders an `<img>` in the list while the other 7 still show initials, then reverted the test photo.

5. `[x]` **`/app/members/[memberId]` Profile box requires scrolling** — too tall, one field per line. Remove Member number from the page header (above the profile box) and reorganize the Profile box into compact rows: Line 1: Full name, Member number. Line 2: Sex, Date of birth, Address. Line 3: Phone, Email, Id number. Line 4: Height (cm), Weight (kg). Line 5: Home branch, Join date, Registered by. Line 6: RFID Tag.
   Also: in RTL languages (AR, HE) the mobile number displays as `Number+` instead of `+Number` — looks like a CSS/bidi issue, since copy-pasting the number into an LTR context shows it correctly as `+Number`.
   Fixed: removed the duplicate member number from the page header; regrouped the Profile card's `dl` into 6 flex-wrap rows matching the requested grouping (empty optional rows are skipped entirely rather than rendering a blank row). Root-caused the phone bug: `<html dir="rtl">` is set app-wide for ar/he (`app/layout.tsx`), and a plain string like `+972521112222` has no strong-direction characters, so the Unicode bidi algorithm reorders the leading `+` to the visual end inside an RTL context — confirmed via rendered HTML (`dir="rtl"` on `<html>`, phone text un-isolated). Added a reusable `PhoneNumber` component (`components/phone-number.tsx`) that wraps the value in `<span dir="ltr">`, forcing a stable left-to-right run regardless of ambient direction, and applied it everywhere a phone number is displayed (not input fields): member profile (own + emergency contact), members list, branch detail, branches list, employee detail, upcoming-birthdays report. Verified on disposable dev servers: in `ar` the phone still renders as `<span dir="ltr">+972521112222</span>` inside the `dir="rtl"` page, i.e. always `+` first.

6. `[x]` **Full member profile page redesign** — user supplied `profile.html`, a self-designed mockup (dark "pine" member card with avatar/photo, status/branch/member-number badges, RFID chip, quick facts strip, action buttons; a quick-actions rail; Identity+Contact and Emergency-contact+Physical-profile panels; Memberships panel with a days-left meter; Payments panel) and asked for the whole `/app/members/[memberId]` page to be rebuilt to match it.
   Fixed: rebuilt the page end-to-end in the new visual language (Archivo + IBM Plex Mono via `next/font/google`, hardcoded hex tokens matching the mockup's "pine/mist/volt" palette, 18px radii). Computed fields not in the old page: age (from DOB), BMI (from height+weight), and a membership days-left progress meter. Added a small RTL-script detector (`isRtlText`, Unicode Hebrew/Arabic ranges) so individual data values (member name, address, registered-by employee, plan name, emergency contact name) get `dir="rtl"` isolated per-value regardless of the page's own UI language — same isolation technique as the `PhoneNumber` fix in note 5, reused for phone fields here too. Preserved all existing functionality (edit, QR, record payment/sell membership, renew, freeze/unfreeze, emergency-contact and medical-notes display) — none of it was dropped, only restyled. Added ~15 new i18n keys (identity/contact/physical-profile titles, age, BMI, days-left sing/plural, empty-state copy, bare height/weight stat labels to avoid duplicating the unit already baked into the existing `t.members.height/weight` labels) in en/ar/he. Verified on disposable dev servers in both English and Arabic: all panels render, RTL isolation confirmed on the member name and phone, a temporarily-added RFID tag rendered the chip correctly then was reverted, no `NaN`/error leaks in the rendered HTML. `tsc --noEmit`, lint, and full production build all clean.
