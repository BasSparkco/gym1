Task Specification: Implement In-App WhatsApp Chat IntegrationObjective:Build an in-app 2-way chat interface inside our Web/ERP application using our existing headless browser instance (Chromium/Puppeteer/WhatsApp Web JS). This will allow staff to chat with members directly from the app without paying Meta API fees or leaving the CRM.System Architecture & Data FlowIncoming Messages (Member $\rightarrow$ Club):Hook into the existing Chromium/WhatsApp session to listen for incoming message events (on('message')).Match incoming phone numbers to the internal member_id.Store the message in the DB (messages table: id, conversation_id, sender_type, body, timestamp).Broadcast the message in real time to the frontend via WebSockets (Socket.io).Outgoing Messages (Staff $\rightarrow$ Member):Staff types a message in the custom Chat UI and clicks Send.Frontend posts the payload to the Backend API (POST /api/chat/send).The server pushes the outgoing message task into a message queue (e.g., BullMQ / Redis).The queue worker picks up the job and dispatches the message via the active Chromium session.Broadcast status (sent/delivered) back to the UI via WebSockets.Key Requirements & SafeguardsMessage Queue: Use a FIFO queue (e.g., BullMQ) to stagger outgoing messages and prevent conflicts between automated system triggers (reminders, billing) and manual staff messages.Session Persistence: Store Chromium’s userDataDir persistently on the server so the session survives restarts without requiring QR re-scans.Database Schema:conversations: (id, member_id, last_message_at, unread_count)messages: (id, conversation_id, sender_type: 'staff'|'member'|'system', content, status, created_at)
